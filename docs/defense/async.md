# Defense: Async и concurrency

- **Контекст:** Синхронные вызовы внутри Event Loop блокируют выполнение других задач на время вызова. В
  `app/api/search.py:24, 56, 78, 107` обработчик асинхронный, а синхронные операции вынесены через `run_in_threadpool`.
  Такой же подход используется для генерации эмбеддингов (`app/services/embedding_service.py:12, 18, 21`).

- **Варианты:**
    - **B. `run_in_threadpool` / `asyncio.to_thread`** — вынести синхронные вызовы в потоки и сохранить существующие
      синхронные клиенты. Минусы: ограниченный пул потоков и накладные расходы.
    - **C. Объявить обработчик как `def`** — FastAPI выполнит его в потоке, но текущий `search()` использует `await`
      (`app/api/search.py:24, 56, 78, 107`), поэтому простая замена `async def` на `def` не подходит.
    - **D. Перейти на асинхронные драйверы** — использовать асинхронные клиенты Redis и БД и переписать соответствующий
      слой на асинхронные операции. Это позволит отказаться от потоков для этих I/O-вызовов, но потребует миграции
      клиентов, сессий, запросов и тестов.
    - **E. Вынести CPU-bound работу в отдельные процессы** — может помочь с вычислениями, которые ограничены GIL, но
      добавляет накладные расходы на межпроцессное взаимодействие.

- **Выбор:** B — `run_in_threadpool`, потому что позволяет сохранить существующий синхронный слой и точечно вынести
  блокирующие вызовы без масштабной миграции. Вариант C несовместим с текущим асинхронным обработчиком без переработки
  его логики. Вариант D архитектурно устраняет необходимость оборачивать соответствующие I/O-вызовы в потоки, но требует
  существенно большего объёма изменений. Поэтому B — компромисс между объёмом работ и отзывчивостью Event Loop, а не
  устранение всех блокировок в приложении.

- **Цена:** Пул потоков ограничен, переключение между потоками имеет накладные расходы, а потоки не гарантируют
  ускорения CPU-bound кода из-за GIL. Кроме того, в `process_document_background()` остаются синхронные вызовы,
  способные блокировать Event Loop: `chunk_text` (`app/services/document_service.py:59`), `bulk_save_objects` (`:72`),
  `query().update()` (`:74`) и `invalidate_search_cache()` (`:81`). Последняя функция использует синхронный
  Redis-клиент — `scan_iter` и `delete` (`app/services/document_service.py:38–43`).
